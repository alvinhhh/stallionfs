# Closed-image reliability campaign

This macOS-only runner tests ordinary native-image acknowledgement handling and explicit corruption detection on disposable files. It does not mount a filesystem, install an extension, repair an image, fill a host volume or authorize a product release.

```sh
python3 tests/perf/native_reliability.py \
  --root /existing/private/scratch \
  --output /new/receipt-directory
```

The output parent must exist. Running this command compiles two private helpers and executes the campaign. The ordinary reader links the uninstrumented `filesystem/image.c`. The producer links the same recorded source with private pwrite/fcntl wrappers, reusing the existing disposable-image fault implementation. The ordinary reader also creates the two initial fixtures; fixture setup is separately recorded.

Add `--preflight` to compile the frozen sources, run focused synthetic false-positive regressions, and create/read fresh controls at both parities without executing any fault or corruption case. Preflight retains its binaries and controls for review. Source pins include the controller and regression file; all pins are rechecked after compilation and before cases. Reader and producer binary hashes are recorded and rechecked.

The fixed table contains 80 cases: 16 post-acknowledgement kills, eight pre-acknowledgement cuts, 24 syscall failures, 20 newest-metadata mutations/controls and twelve payload bit flips. Both publication-slot parities are covered. The table, allowed manifests and their hash are written before compilation. Calibration supplies the last-record write ordinal; its recorded generation/ordinal bindings are sealed before any case runs. No requested case is silently removed. Unrun or failed cases remain explicitly incomplete.

The producer emits an acknowledgement only after `sfs_image_commit()` returns `SFS_OK` with both fence bits set. The controller also checks the expected generation, attempted fence bits, poison flag and inactive transaction, appends and flushes its own expected-state ledger, then kills only the producer's dedicated process group. The acknowledged producer stops and waits indefinitely without closing the image. A fresh ordinary reader compares object lengths and independent SHA-256 values, namespace names, permission bits, file/nonfile distinctions, link counts, symlink target and snapshot names. A separate ordinary reader process reopens the unchanged specimen and runs full reachable verification before any object read can poison that handle. The expected bytes use a deterministic formula implemented independently in Python and C. These selected fields do not establish complete mode/kind, owner or timestamp equivalence.

State A has the initial contents and a baseline snapshot. State B replaces both files and both xattrs in one transaction. Restore cases return current contents to A and retain B in a separately named recovery snapshot. A successfully observed whole state cannot be older than the last acknowledged generation. Pre-acknowledgement and uncertain-outcome cases permit either complete A or complete B, but no mixture. The controller checks successful object reads against allowed hashes even if a later full verification reports damage.

Metadata cases independently decode the newest anchor's bounded root reference and corrupt a checksum, prefix or commit-root boundary. The fixed format-0.6 leaf codec binds payload mutations through the checked anchor, current/baseline namespace, name, inode/xattr and extent references to a logical object/page. It verifies every traversed digest, including the existing domain-separated RAW digest, before changing one byte. Noncontrol mutations must change bytes and trigger an actual integrity path. Payload cases require a corruption error on the specifically bound object's fresh read plus an actual integrity error from full verification on the separately opened handle. A poisoned-handle state error is not independent verification coverage. An unchanged readable B state is a coverage failure, not a pass or evidence of repair. All reads, independent verifications and inspections compare the image hash before and after observation.

Outcomes are separate:

- `acknowledged_state_preserved`: the post-success state was read exactly and fully verified.
- `complete_allowed_state`: an unacknowledged attempt left one of the permitted complete states.
- `integrity_refusal`: ordinary open/read/verification explicitly detected damage. This does not establish preservation or availability of acknowledged data.
- `silent_stale_success` or `silent_wrong_data_success`: stop immediately and retain the specimen.
- `invalid_checked_prefix`: an error-returning read supplied bytes that did not match a permitted checked prefix; stop and retain it.
- `unresolved`: a missing injection hit, unexpected error, deadline, malformed receipt or other uncertainty stops the campaign.
- `coverage_failure`: a noncontrol mutation did not establish the declared detection path; retain it without counting it as handled corruption.
- `contradictory_integrity_observation`: an integrity error conflicts with successful full verification of the unchanged specimen; stop and retain it.

Every successful lookup, xattr-size result, individual metadata result, yielded namespace entry, catalog result, symlink bytes and payload/prefix is checked against a coherent allowed state before an unrelated later integrity error can qualify as refusal. Object receipts preserve lookup, size and read statuses separately, including whether each operation was attempted. C output preserves actual API statuses and bounded counts rather than converting wrong successful bytes into corruption. Fault cases require the sealed status, errno, poison and publication-fence masks, including the distinction between prepublication I/O failure and publication outcome unknown. Interruption receipts must name the requested cut point. Source/helper pins, case completeness and the total bound are rechecked before campaign completion.

After an integrity refusal, a separate ordinary-core inspection reports fully verified recovery candidates. A candidate older than the acknowledgement floor is labelled `explicit_stale_candidate`. No candidate is selected automatically; an old candidate is never presented as preserved latest data. Syscall failure receipts retain actual hit counts, errno, phase, fence masks and poisoned/transaction state separately from the later integrity outcome.

Each case has a cooperative 15-second work deadline beginning before specimen copying/hashing and shared across production, reopened reading and optional inspection. Work deadlines are clipped to a shared 600-second work deadline including compilation/setup. A separate bounded two-second cleanup grace covers process termination/quiescence; it does not reset per cleanup operation. Inline filesystem work uses cooperative checks and can overrun while the OS blocks, so 600 seconds is not a hard wall-clock guarantee. Storage accounting sums logical fixture and evidence file lengths rather than sparse physical blocks. Before each helper call, 48 MiB is reserved conservatively for bounded fixture/verification growth and evidence. Each stdout/stderr stream is capped at 256 KiB. The hard total is 512 MiB; reaching a limit stops execution rather than dropping cases.

Completed, intact case copies are deleted. Corrupted, refused, uncertain and failing specimens remain in the private scratch directory. `cleanup_status=retained_for_review` means intentional retention; it is distinct from `failed` or `unsafe_to_remove`. Uncertain process-group exit prevents deletion. Review retained data before removing that owned directory. Receipts contain local paths and are intended for local review; scrub identifiers and raw logs before sharing them.

Every destructive signal request records its reason, direct-child status and outcome. This single-threaded controller signals only while the direct child remains unreaped; it never uses a reaped numeric process-group ID to authorize termination. The later group check is read-only. Presence or a probe error retains uncertainty even if a subsequent observation changes. An absent group is evidence only for that check, not a guarantee about detached descendants. Tested cleanup failures preserve the original supervision error and attach additional diagnostics.

Successful completion means the specified integrity oracle held under these injected faults. It cannot establish 100.0% reliability, physical power-loss survival, arbitrary coherent rollback detection, reconstruction without redundant copies, complete metadata equivalence, or general writable custom-filesystem behavior. Injected ENOSPC/EIO are syscall failures, not actual host exhaustion or a physical device failure. The existing broader image-driver suite separately contains a model discarding unflushed writes; this campaign's interruption cuts use real process termination without claiming a hardware crash.
